# Work Manager — PRD (초안 v0.2)

> 상태: 초안 · 작성일 2026-11-03
> v0.2 변경: 다중 팀 소속 + 팀별 활성/비활성, 팀 이동 제거, TODO 작성자/담당자 분리 없음, DB MySQL.
> 미결 항목은 [open-questions.md](open-questions.md) 참고.

## 1. 한 줄 요약

팀 단위로 TODO, 이슈, 배포일정, 연차를 관리하고, 필요한 때에 슬랙으로 알려주며, 한 주와 한 달의 업무를 통계로 돌아볼 수 있는 사내 업무 관리 도구.

## 2. 해결하려는 문제

- 할 일이 메모, 슬랙, 머릿속에 흩어져 있어서 놓친다.
- 어떤 작업에서 어떤 이슈가 있었는지 나중에 찾기 어렵다.
- 주간/월간 보고 때마다 한 일을 다시 떠올려야 한다.
- 배포일정, 연차 공유가 구두나 슬랙 메시지로만 이뤄져 기록이 남지 않는다.

## 3. 사용자와 역할

| 역할 | 설명 |
|---|---|
| 슈퍼 관리자 | 팀과 계정을 관리한다. **팀의 업무 내용은 볼 수 없다.** |
| 팀 관리자 | 팀원의 내용을 **조회만** 한다(비공개 열람은 슈퍼 관리자의 팀별 설정에 따름). TODO 유형을 관리한다. 팀당 최대 2명. |
| 팀원 | 본인 TODO, 이슈, 배포일정, 연차를 등록하고 팀 공유 내용을 본다. |

- 한 사람은 **여러 팀에 소속**될 수 있고, 역할과 활성 상태는 팀마다 따로 가진다.
- 로그인 후 작업할 팀을 선택한다. **비활성 소속인 팀으로는 들어갈 수 없다.**
- 팀 간 데이터는 완전히 격리된다(멀티테넌트). 1팀으로 들어오면 2팀의 어떤 내용도 볼 수 없다. 두 팀에 모두 소속된 사람도 마찬가지다.
- 상세 권한은 [permissions.md](permissions.md) 참고.

## 4. 기능 범위와 단계

| 단계 | 기능 | 핵심 |
|---|---|---|
| Phase 0 | 계정, 팀, 권한, 로그인 | 멀티테넌트 기반 |
| Phase 1 | TODO + 알림 + 알림함 | 알림 엔진 완성 |
| Phase 2 | 이슈 저장소 | TODO와 연결 |
| Phase 3 | 주간/월간 통계 | TODO, 이슈 데이터 집계 |
| Phase 4 | 배포일정, 연차 | 알림 엔진 재사용 |
| Phase 5 | 점심 메뉴 룰렛 | 독립 모듈 |

## 5. 기능 요약

### 5.1 계정 / 팀 ([features/account.feature](../features/account.feature))
- 슈퍼 관리자가 계정을 생성하고 팀 소속(팀 + 역할)을 추가한다. 사용자는 첫 로그인 시 비밀번호를 변경한다.
- 아이디/비밀번호 로그인 → 활성 팀이 여러 개면 팀 선택.
- 팀 이동 기능은 없다. 새 팀 소속을 추가하고 기존 소속을 비활성화한다. 비활성화되어도 데이터와 이름은 그 팀에 남는다.

### 5.2 TODO ([features/todo.feature](../features/todo.feature))
- TODO는 **내가 해야 할 일**이다. 작성자가 곧 수행자이며, 다른 사람에게 할당할 수 없다.
- **기간 TODO**: 일(오늘), 주(이번 주), 월(이번 달) 중 하나의 기간에 속하는 할 일.
- **반복 TODO**: 매일 / 평일 / 매주 특정 요일 / 매월 특정 일에 자동 생성.
- **유형**: 팀 관리자가 팀별로 만든다(예: 개발, 회의, 리뷰).
- **공개 범위**: 팀 공개(기본) / 비공개. 비공개는 본인만 보며, 팀 설정에 따라 팀 관리자도 볼 수 있다.
- **알림**: TODO에 알림 일시를 지정하면 그 시각에 슬랙으로 알린다.

### 5.3 이슈 저장소 ([features/issue.feature](../features/issue.feature))
- 작업 중 발생한 이슈(문제, 원인, 해결)를 기록한다.
- 이슈는 TODO에 연결할 수 있다(TODO 1 : 이슈 N). 연결 없이 독립 이슈도 가능.
- 이슈의 공개 범위는 연결된 TODO를 따른다. 독립 이슈는 팀 공개 기본, 비공개 선택 가능.

### 5.4 주간 / 월간 통계 ([features/summary.feature](../features/summary.feature))
- AI 요약 대신 통계로 시작한다(AI 요약은 이후 확장 후보).
- 주간: 월~금 기준. 월간: 해당 월 1일~말일.
- 지표: 완료/미완료 건수와 완료율, 유형별 건수, 지연된 TODO, 등록된 이슈 수, 연차 일수.
- 금요일 17:00에 주간 통계를 슬랙으로 발송.

### 5.5 배포일정 ([features/deploy.feature](../features/deploy.feature))
- 개인 단위로 등록하며 배포 담당자 1명을 지정한다(TODO와 달리 배포는 담당자 지정이 있음).
- 팀 내 공유. 담당자에게 슬랙 알림.

### 5.6 연차 ([features/leave.feature](../features/leave.feature))
- 승인 절차 없음. 공유 목적.
- 종류: 연차, 오전 반차, 오후 반차. 팀 캘린더에 표시.
- 연차 전날 17:00에 본인에게 슬랙 알림.

### 5.7 알림 ([features/notification.feature](../features/notification.feature))
- 1단계: 사용자가 본인 Slack Incoming Webhook URL을 등록(나만 있는 비공개 채널). 슬랙 연동은 계정당 1개.
- 2단계: Slack Bot으로 개인 DM 발송(슬랙 이메일 연동).
- 나중에 알림 종류별로 팀 채널 발송 가능하도록 확장.
- 모든 알림은 서비스 내 **알림함**에도 남는다.
- PC가 꺼져 있어 발송 시각을 놓친 알림은 **슬랙으로 보내지 않고** 알림함에만 "미발송"으로 남긴다.

### 5.8 점심 메뉴 룰렛 ([features/lunch.feature](../features/lunch.feature))
- 팀별 메뉴 목록 관리(팀원 누구나), 룰렛으로 하나 추첨.
- 다른 기능과 의존하지 않는 독립 모듈로 만든다. 애드온 구조는 Phase 5에서 결정.

## 6. 비기능 요구사항

| 항목 | 내용 |
|---|---|
| 실행 환경 | 개발은 로컬 PC에서 진행하고, 이후 서버에 배포한다. 배포 전까지는 서버가 꺼져 있으면 알림이 발송되지 않음 |
| 기술 스택 | Backend: Java 21, Spring Boot 3 · Frontend: React + TypeScript (Vite) · DB: MySQL 8 |
| 저장소 | 단일 레포(모노레포): `backend/`, `frontend/`, `docs/`, `features/` |
| 보안 | 비밀번호 해시 저장, Webhook URL/Slack 토큰은 암호화 저장 |
| 데이터 격리 | 모든 팀 데이터에 `team_id`, 모든 조회에 현재 팀 필터 강제 |
