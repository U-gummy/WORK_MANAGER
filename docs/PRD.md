# Work Manager — PRD (초안 v0.3)

> 상태: 초안 · 작성일 2026-11-04
> v0.3 변경: **작게 시작.** 단일 팀, 관리자 1명 + 팀원. 슈퍼 관리자, 다중 팀, 팀 선택, 비공개 기능 제거.
> 결정 사항과 미결 항목은 [open-questions.md](open-questions.md) 참고.

## 1. 한 줄 요약

한 팀이 TODO, 이슈, 배포일정, 연차를 함께 관리하고, 필요한 때에 팀 슬랙 채널로 알려주며, 한 주와 한 달의 업무를 통계로 돌아볼 수 있는 업무 관리 도구.

## 2. 해결하려는 문제

- 할 일이 메모, 슬랙, 머릿속에 흩어져 있어서 놓친다.
- 어떤 작업에서 어떤 이슈가 있었는지 나중에 찾기 어렵다.
- 주간/월간 보고 때마다 한 일을 다시 떠올려야 한다.
- 배포일정, 연차 공유가 구두나 슬랙 메시지로만 이뤄져 기록이 남지 않는다.

## 3. 사용자와 역할

서비스 하나 = 팀 하나. 팀 선택이나 팀 간 격리는 없다.

| 역할 | 인원 | 설명 |
|---|---|---|
| 관리자 | **정확히 1명** | 팀원이 하는 모든 일 + 계정 관리, TODO 유형, 슬랙 채널, 공휴일 관리, 관리자 위임 |
| 팀원 | 제한 없음 | 본인 TODO, 이슈, 배포일정, 연차를 등록하고 팀 전체 내용을 본다 |

- **모든 업무 데이터는 팀 전체에 공개**된다. 비공개 기능은 없다.
- 수정과 삭제는 **본인이 만든 것만** 할 수 있다. 관리자도 다른 사람의 업무 데이터는 수정하지 않는다.
- 상세 권한은 [permissions.md](permissions.md) 참고.

## 4. 기능 범위와 단계

| 단계 | 기능 | 핵심 |
|---|---|---|
| Phase 0 | 계정, 로그인, 관리자 | 최초 관리자 생성, 계정 관리 |
| Phase 1 | TODO + 알림 + 알림함 + 대시보드 | 알림 엔진 완성 |
| Phase 2 | 이슈 저장소 | TODO와 연결 |
| Phase 3 | 주간/월간 통계 | TODO, 이슈 데이터 집계 |
| Phase 4 | 배포일정, 연차 | 알림 엔진 재사용 |
| Phase 5 | 점심 메뉴 룰렛 | 독립 모듈 |

## 5. 기능 요약

### 5.1 계정 / 로그인 ([features/account.feature](../features/account.feature), [features/bootstrap.feature](../features/bootstrap.feature))
- 첫 관리자는 최초 실행 시 환경변수로 생성한다.
- 관리자가 팀원 계정을 만들고 임시 비밀번호를 전달한다. 사용자는 첫 로그인 시 비밀번호를 변경한다.
- 아이디/비밀번호 로그인(서버 세션). 로그인하면 바로 대시보드로 간다.
- 퇴사 등으로 계정을 **비활성화**하면 로그인할 수 없고, 작성한 데이터와 이름은 "(비활성)" 표시와 함께 남는다.
- 관리자는 다른 팀원에게 **관리자를 위임**할 수 있다. 위임하면 본인은 팀원이 된다. 관리자는 항상 1명이다.

### 5.2 TODO ([features/todo.feature](../features/todo.feature))
- TODO는 **내가 해야 할 일**이다. 작성자가 곧 수행자이며, 다른 사람에게 할당할 수 없다.
- **기간 TODO**: 일(오늘), 주(이번 주), 월(이번 달) 중 하나의 기간에 속하는 할 일.
- **반복 TODO**: 매일 / 평일 / 매주 특정 요일 / 매월 특정 일에 자동 생성. 규칙을 수정하면 이후 생성분부터 반영.
- **이월**: 기간이 지난 미완료 TODO를 오늘 또는 이번 주로 옮긴다. 원래 기간과 이월 횟수가 남는다.
- 완료 취소와 기간 변경(일 ↔ 주 ↔ 월)을 할 수 있다.
- **유형**: 관리자가 만든다(예: 개발, 회의, 리뷰).
- **알림**: TODO에 알림 일시를 지정하면 그 시각에 팀 슬랙 채널로 알린다(본인 멘션).

### 5.3 이슈 저장소 ([features/issue.feature](../features/issue.feature))
- 작업 중 발생한 이슈(문제, 원인, 해결)를 기록한다.
- 이슈는 TODO에 연결할 수 있다(TODO 1 : 이슈 N). 연결 없이 독립 이슈도 가능.

### 5.4 주간 / 월간 통계 ([features/summary.feature](../features/summary.feature))
- AI 요약 대신 통계로 시작한다(AI 요약은 이후 확장 후보).
- 주간: 월~금 기준. 월간: 해당 월 1일~말일.
- 지표: 완료/미완료 건수와 완료율, 유형별 건수, 지연된 TODO, 등록된 이슈 수, 지난주 대비.
- 집계 기준: 주간 통계는 기간이 그 주(월~금)에 걸친 일·주 TODO, 월간 TODO는 월간 통계에만 포함. 완료율 = 완료 / 집계 대상.
- 팀원은 본인 통계를 보고, **관리자는 팀원별 통계**도 본다.
- 금요일 17:00에 **팀 합계** 주간 통계를 팀 슬랙 채널로 발송한다.

### 5.5 배포일정 ([features/deploy.feature](../features/deploy.feature))
- 개인 단위로 등록하며 배포 담당자 1명을 지정한다(TODO와 달리 배포는 담당자 지정이 있음).
- 팀 전체에 공유. 배포 1시간 전에 담당자를 멘션해서 팀 채널로 알린다.

### 5.6 연차 ([features/leave.feature](../features/leave.feature))
- 승인 절차 없음. 공유 목적.
- 종류: 연차, 오전 반차, 오후 반차. 팀 캘린더에 표시.
- 기간으로 등록하면 주말과 공휴일은 빠진다. 공휴일은 관리자가 연 1회 입력한다.
- 연차 전날 17:00에 팀 채널로 "내일 김철수 연차" 형태로 공유(본인 멘션).

### 5.7 알림 ([features/notification.feature](../features/notification.feature))
- **관리자가 팀 슬랙 채널 1개**를 등록한다(Incoming Webhook URL). 등록하지 않으면 알림은 알림함에만 남는다.
- 관리자는 알림 종류별로 채널 발송을 켜고 끌 수 있다.
- 사용자가 본인 설정에 슬랙 멤버 ID를 등록하면 채널 메시지에서 **@멘션**된다. 등록하지 않으면 이름만 표시된다.
- 모든 개인 알림은 서비스 내 **알림함**에도 남는다(90일 보관).
- PC가 꺼져 있어 발송 시각을 놓친 알림은 **슬랙으로 보내지 않고** 알림함에만 "미발송"으로 남긴다.
- 이후 확장 후보: Slack Bot으로 개인 DM 발송.

### 5.8 점심 메뉴 룰렛 ([features/lunch.feature](../features/lunch.feature))
- 메뉴 목록 관리(누구나), 룰렛으로 하나 추첨.
- 아무 날이나 쓸 수 있고, 금요일에는 대시보드에 바로가기를 보여준다.
- 다른 기능과 의존하지 않는 독립 모듈로 만든다. 애드온 구조는 Phase 5에서 결정.

### 5.9 대시보드 ([features/dashboard.feature](../features/dashboard.feature))
- 로그인 후 첫 화면. **오늘 할 일, 이번 주 할 일, 오늘 부재자, 다가오는 배포**를 보여준다.
- 지연된 TODO가 있으면 이월을 안내한다.

## 6. 비기능 요구사항

| 항목 | 내용 |
|---|---|
| 실행 환경 | 개발은 로컬 PC에서 진행하고, 이후 서버에 배포한다. 배포 전까지는 서버가 꺼져 있으면 알림이 발송되지 않음 |
| 기술 스택 | Backend: Java 21, Spring Boot 3, Spring Data JPA · Frontend: React + TypeScript (Vite) · DB: MySQL 8 |
| 저장소 | 단일 레포(모노레포): `backend/`, `frontend/`, `docs/`, `features/` |
| 인증 | 서버 세션. 매 요청마다 계정 활성 여부를 확인해 비활성화 즉시 차단 |
| 보안 | 비밀번호 BCrypt 해시, 5회 실패 시 잠금. Webhook URL은 암호화 저장하고 화면에는 일부만 표시 |
| 데이터 보관 | 알림함은 90일 후 삭제. 로컬 MySQL은 일 1회 덤프로 백업 |
| 슬랙 발송 | 같은 시각의 알림은 순차 발송(Webhook 속도 제한 대응) |

## 7. 범위 밖 (지금은 하지 않음)

- 여러 팀, 팀 간 데이터 격리, 슈퍼 관리자 → 필요해지면 이후 확장
- 비공개 TODO/이슈
- 감사 로그
- 연차 승인 결재
- AI 요약
- TODO 할당 (다른 사람에게 일 맡기기)
- 슬랙 안에서의 상호작용(버튼으로 완료 처리 등)
- 서버 배포 (개발 완료 후 별도 진행)
