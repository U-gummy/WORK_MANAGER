# Work Manager — PRD (초안 v0.5)

> 상태: 초안 · 작성일 2026-11-04
> v0.5 변경: 고객사 속성, 플로우 링크, 월간 보고서 추가. 이슈를 프로젝트에 바로 연결.
> v0.4 변경: 프로젝트 > 업무 > 할 일 구조 추가. 이슈는 업무에 연결.
> v0.3 변경: **작게 시작.** 단일 팀, 관리자 1명 + 팀원. 슈퍼 관리자, 다중 팀, 팀 선택, 비공개 기능 제거.
> 결정 사항과 미결 항목은 [open-questions.md](open-questions.md) 참고.

## 1. 한 줄 요약

유지보수가 많은 한 팀이 **프로젝트(시스템) > 업무 > 할 일**로 일을 묶어 할 일, 이슈, 배포일정, 연차를 함께 관리하고, 필요한 때에 팀 슬랙 채널로 알려주며, 한 주와 한 달의 업무를 통계와 월간 보고서로 돌아볼 수 있는 업무 관리 도구. 요청의 원본은 전사 도구 "플로우"에 두고, 이 도구는 처리 기록을 남긴다.

## 2. 해결하려는 문제

- 할 일이 메모, 슬랙, 머릿속에 흩어져 있어서 놓친다.
- 어떤 작업에서 어떤 이슈가 있었는지 나중에 찾기 어렵다.
- 주간/월간 보고 때마다 한 일을 다시 떠올려야 한다.
- 배포일정, 연차 공유가 구두나 슬랙 메시지로만 이뤄져 기록이 남지 않는다.
- 요청과 업무는 플로우에 있지만, 내가 그 일을 어떻게 처리했는지(한 일, 겪은 이슈)는 어디에도 남지 않는다.
- 시스템(고객사)별로 한 달 동안 무엇을 처리했는지 정리하기 어렵다.

## 3. 사용자와 역할

서비스 하나 = 팀 하나. 팀 선택이나 팀 간 격리는 없다.

| 역할 | 인원 | 설명 |
|---|---|---|
| 관리자 | **정확히 1명** | 팀원이 하는 모든 일 + 계정 관리, 프로젝트와 고객사 관리, 할 일 유형, 슬랙 채널, 공휴일 관리, 관리자 위임 |
| 팀원 | 제한 없음 | 업무, 본인 할 일, 이슈, 배포일정, 연차를 등록하고 팀 전체 내용을 본다 |

- **모든 업무 데이터는 팀 전체에 공개**된다. 비공개 기능은 없다.
- 수정과 삭제는 **본인이 만든 것만** 할 수 있다. 관리자도 다른 사람의 업무 데이터는 수정하지 않는다.
- 상세 권한은 [permissions.md](permissions.md) 참고.

## 4. 기능 범위와 단계

| 단계 | 기능 | 핵심 |
|---|---|---|
| Phase 0 | 계정, 로그인, 관리자 | 최초 관리자 생성, 계정 관리 |
| Phase 1 | 프로젝트, 업무, 할 일 + 알림 + 알림함 + 대시보드 | 알림 엔진 완성, 프로젝트 뱃지 |
| Phase 2 | 이슈 저장소 | 업무, 프로젝트, 할 일과 연결 |
| Phase 3 | 주간/월간 통계, 월간 보고서 | 할 일, 이슈, 배포 데이터 집계 |
| Phase 4 | 배포일정, 연차 | 알림 엔진 재사용 |
| Phase 5 | 점심 메뉴 룰렛 | 독립 모듈 |

> 대시보드의 "오늘 부재자", "다가오는 배포" 영역과 월간 보고서의 배포 내역은 Phase 4(배포일정, 연차) 전까지 비어 있다. 단계를 앞당길지는 Phase 1을 시작할 때 정한다.

## 5. 기능 요약

### 5.1 계정 / 로그인 ([features/account.feature](../features/account.feature), [features/bootstrap.feature](../features/bootstrap.feature))
- 첫 관리자는 최초 실행 시 환경변수로 생성한다.
- 관리자가 팀원 계정을 만들고 임시 비밀번호를 전달한다. 사용자는 첫 로그인 시 비밀번호를 변경한다.
- 아이디/비밀번호 로그인(서버 세션). 로그인하면 바로 대시보드로 간다.
- 퇴사 등으로 계정을 **비활성화**하면 로그인할 수 없고, 작성한 데이터와 이름은 "(비활성)" 표시와 함께 남는다.
- 관리자는 다른 팀원에게 **관리자를 위임**할 수 있다. 위임하면 본인은 팀원이 된다. 관리자는 항상 1명이다.

### 5.2 프로젝트와 업무 ([features/project.feature](../features/project.feature))

일을 세 단계로 묶는다.

```
프로젝트 (몇 달)   쇼핑몰 리뉴얼 [파랑 뱃지]       ← 관리자가 만듦
 └ 업무 (몇 주)    로그인 기능 개발 11/03~11/13   ← 누구나 만듦
    ├ 할 일 (하루~한 달)  로그인 API 개발 11/03
    ├ 이슈              세션 만료 시 무한 리다이렉트
    └ 배포              v1.2.0 운영 배포
```

- **프로젝트는 시스템 단위**로 만든다(예: A사 쇼핑몰, A사 ERP). 고객사 전체에 걸친 일은 "A사 공통" 같은 프로젝트에 담는다.
- **고객사**는 프로젝트에 붙는 속성이다. 관리자가 프로젝트를 등록할 때 고르거나 새로 입력한다. 할 일은 프로젝트만 고르고, 목록과 보고서는 고객사로도 걸러 볼 수 있다.
- **프로젝트**: 이름과 색을 가진다. 색은 할 일, 업무, 이슈, 배포에 **뱃지**로 표시된다. 관리자가 등록하고 종료한다. 종료된 프로젝트는 선택 목록에서 빠지지만 기록은 남는다.
- **업무**: 반드시 하나의 프로젝트에 속한다. 시작일과 종료일, 상태(진행 중/완료)를 가진다. 누구나 등록하고, 작성자만 수정과 완료를 할 수 있다.
- **업무 상세**에서 그 업무의 할 일(누가 했든), 이슈, 배포를 한 번에 본다. "어떤 작업에 어떤 이슈가 있었는지"에 대한 답이 이 화면이다.
- 할 일, 이슈, 배포는 **업무 또는 프로젝트에 선택적으로** 연결한다. 업무를 고르면 프로젝트는 자동으로 정해지고, 따로 바꿀 수 없다.
- 할 일 목록, 이슈 목록, 배포 캘린더는 **프로젝트나 고객사로 걸러 볼 수 있다.**

#### 플로우와의 역할 분담

| | 플로우 (전사 협업 도구) | 이 도구 |
|---|---|---|
| 누가 | 기획자, 고객사 소통 | 실제로 일하는 사람 |
| 무엇을 | 요청과 업무의 **원본** | 내 할 일, 이슈, 배포, 연차 등 **처리 기록** |

- 플로우의 큰 업무를 여러 날에 걸쳐 처리할 때만 이 도구에 업무를 만들고, 작은 건은 프로젝트에 바로 할 일을 만든다.
- 업무와 할 일에 **플로우 링크**를 붙여 원본으로 바로 갈 수 있게 한다. 같은 내용을 두 번 쓰지 않는다.
- 플로우와의 자동 연동은 하지 않는다(API 제공 여부 미확인, 범위 밖).

### 5.3 할 일 ([features/todo.feature](../features/todo.feature))
- 할 일은 **내가 해야 할 일**이다. 작성자가 곧 수행자이며, 다른 사람에게 할당할 수 없다.
- **기간 할 일**: 일(오늘), 주(이번 주), 월(이번 달) 중 하나의 기간에 속하는 할 일.
- **반복 할 일**: 매일 / 평일 / 매주 특정 요일 / 매월 특정 일에 자동 생성. 규칙을 수정하면 이후 생성분부터 반영.
- **이월**: 기간이 지난 미완료 할 일을 오늘 또는 이번 주로 옮긴다. 원래 기간과 이월 횟수가 남는다.
- 완료 취소와 기간 변경(일 ↔ 주 ↔ 월)을 할 수 있다.
- **유형**: 관리자가 만든다(예: 개발, 회의, 리뷰).
- **알림**: 할 일에 알림 일시를 지정하면 그 시각에 팀 슬랙 채널로 알린다(본인 멘션).

### 5.4 이슈 저장소 ([features/issue.feature](../features/issue.feature))
- 작업 중 발생한 이슈(문제, 원인, 해결)를 기록한다.
- 이슈는 할 일과 같은 방식으로 **업무 / 프로젝트만 / 없음** 중 하나에 연결한다. 유지보수처럼 특정 업무 없이 시스템에서 생긴 이슈는 프로젝트에 바로 남긴다.
- 남의 할 일에도 이슈를 기록할 수 있다(예: 리뷰하다 발견한 문제). 이슈의 작성자는 기록한 사람이고, 수정과 삭제도 그 사람만 한다.
- 할 일에 기록하면 그 할 일의 업무와 프로젝트를 따라간다(할 일 1 : 이슈 N). 할 일을 삭제해도 이슈는 업무나 프로젝트에 남는다.
- 이슈 목록은 프로젝트나 고객사로 걸러 볼 수 있다.

### 5.5 주간 / 월간 통계 ([features/summary.feature](../features/summary.feature))
- AI 요약 대신 통계로 시작한다(AI 요약은 이후 확장 후보).
- 주간: 월~금 기준. 월간: 해당 월 1일~말일.
- 지표: 완료/미완료 건수와 완료율, 유형별 건수, **프로젝트별 건수**, 지연된 할 일, 등록된 이슈 수, 지난주 대비.
- 주간 통계에는 완료한 할 일 목록(날짜순)을, 월간 통계에는 주차별 완료율 추이를 함께 보여준다.
- 집계 기준: 주간 통계는 기간이 그 주(월~금)에 걸친 일·주 할 일, 월간 할 일은 월간 통계에만 포함. 완료율 = 완료 / 집계 대상.
- 팀원은 본인 통계를 보고, **관리자는 팀원별 통계**도 본다.
- 금요일 17:00에 **팀 합계** 주간 통계를 팀 슬랙 채널로 발송한다. 금요일이 공휴일이면 그 주의 마지막 영업일 17:00에 보낸다.

#### 월간 보고서 ([features/report.feature](../features/report.feature))
- 통계가 숫자로 흐름을 본다면, 보고서는 **문서 형태로 내용을** 본다. 유지보수 이력 정리, 인수인계, 고객사 문의 대응에 쓴다.
- 프로젝트 또는 고객사 하나와 월 하나를 골라서 본다.
- 내용: **처리한 일**(그 달에 완료한 할 일: 제목, 완료일, 작성자), **이슈**(그 달에 등록했거나 해결한 이슈: 제목, 원인, 해결, 상태), **배포**(제목, 일시, 결과).
- 화면에서 보기만 한다. 내보내기는 하지 않는다.

### 5.6 배포일정 ([features/deploy.feature](../features/deploy.feature))
- 개인 단위로 등록하며 배포 담당자 1명을 지정한다(할 일과 달리 배포는 담당자 지정이 있음).
- 업무 또는 프로젝트에 연결할 수 있다.
- 팀 전체에 공유. 배포 1시간 전에 담당자를 멘션해서 팀 채널로 알린다.
- 담당자가 바뀌면 새 담당자에게 바로 알린다. 담당자 계정이 비활성화되면 등록자에게 알리고, 담당자를 다시 정할 때까지 배포 알림도 등록자에게 보낸다.
- 수정, 삭제, 취소는 등록자만 한다. 결과(성공/실패)는 등록자나 담당자가 기록한다.

### 5.7 연차 ([features/leave.feature](../features/leave.feature))
- 승인 절차 없음. 공유 목적.
- 종류: 연차, 오전 반차, 오후 반차. 팀 캘린더에 표시.
- 기간으로 등록하면 주말과 공휴일은 빠진다. 공휴일은 관리자가 연 1회 입력한다.
- 연차 **직전 영업일** 17:00에 팀 채널로 "11/16(월) 김철수 연차" 형태로 공유한다(본인 멘션). 월요일 연차는 금요일에, 전날이 공휴일이면 그 전 영업일에 보낸다.

### 5.8 알림 ([features/notification.feature](../features/notification.feature))
- **관리자가 팀 슬랙 채널 1개**를 등록한다(Incoming Webhook URL). 등록하지 않으면 알림은 알림함에만 남는다.
- 관리자는 알림 종류별로 채널 발송을 켜고 끌 수 있다.
- 사용자가 본인 설정에 슬랙 멤버 ID를 등록하면 채널 메시지에서 **@멘션**된다. 등록하지 않으면 이름만 표시된다.
- 사용자는 본인 설정에서 알림 종류별로 끌 수 있다. 끈 종류는 채널로도 보내지 않고 알림함에도 남기지 않는다.
- 그 밖의 개인 알림은 서비스 내 **알림함**에도 남는다(90일 보관).
- PC가 꺼져 있어 발송 시각을 놓친 알림은 **슬랙으로 보내지 않고** 알림함에만 "미발송"으로 남긴다.
- 이후 확장 후보: Slack Bot으로 개인 DM 발송.

### 5.9 점심 메뉴 룰렛 ([features/lunch.feature](../features/lunch.feature))
- 메뉴 목록 관리(누구나), 룰렛으로 하나 추첨. 결과는 기록한다.
- "최근 2주 제외" 옵션으로 최근에 나온 메뉴를 빼고 돌릴 수 있다.
- 아무 날이나 쓸 수 있고, 금요일에는 대시보드에 바로가기를 보여준다.
- 다른 기능과 의존하지 않는 독립 모듈로 만든다. 애드온 구조는 Phase 5에서 결정.

### 5.10 대시보드 ([features/dashboard.feature](../features/dashboard.feature))
- 로그인 후 첫 화면. **오늘 할 일, 이번 주 할 일, 오늘 부재자, 다가오는 배포**를 보여준다. 할 일에는 프로젝트 뱃지가 붙는다.
- 지연된 할 일이 있으면 이월을 안내한다.

## 6. 비기능 요구사항

| 항목 | 내용 |
|---|---|
| 실행 환경 | 개발은 로컬 PC에서 진행하고, 이후 서버에 배포한다. 배포 전까지는 서버가 꺼져 있으면 알림이 발송되지 않음 |
| 기술 스택 | Backend: Java 21, Spring Boot 3, Spring Data JPA · Frontend: React + TypeScript (Vite) · DB: MySQL 8 |
| 저장소 | 단일 레포(모노레포): `backend/`, `frontend/`, `docs/`, `features/`, `scripts/` |
| 인증 | 서버 세션. 매 요청마다 계정 활성 여부를 확인해 비활성화 즉시 차단 |
| 보안 | 비밀번호 BCrypt 해시, 5회 실패 시 잠금. Webhook URL은 암호화 저장하고 화면에는 일부만 표시 |
| 데이터 보관 | 알림함은 90일 후 삭제. 로컬 MySQL은 일 1회 덤프로 백업 |
| 슬랙 발송 | 같은 시각의 알림은 순차 발송(Webhook 속도 제한 대응) |
