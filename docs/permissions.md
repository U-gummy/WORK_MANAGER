# 권한 설계 (초안 v0.2)

> v0.2 변경: 팀 이동 제거 → 다중 팀 소속 + 팀별 활성/비활성. 작성자/담당자 분리 없음.

## 1. 멀티테넌트 원칙

- **테넌트 = 팀.** 팀에 속한 모든 데이터(TODO, 이슈, 배포일정, 연차, 유형, 메뉴)는 `team_id`를 가진다.
- 사용자는 로그인 후 **하나의 팀을 선택**해서 작업한다. 이 팀을 "현재 팀"이라 한다.
- 모든 조회와 변경은 **현재 팀**으로 자동 필터링된다. 요청 파라미터로 받은 `team_id`는 신뢰하지 않는다.
- 여러 팀에 소속된 사람이라도 **현재 팀이 아닌 팀의 데이터는 보이지 않는다.** 1팀으로 들어오면 2팀 데이터는 볼 수 없다.
- 다른 팀의 데이터 ID로 직접 접근하면 `404 Not Found`로 응답한다(존재 여부를 노출하지 않음).
- 슈퍼 관리자는 어느 팀에도 속하지 않으며, 팀의 업무 데이터에 접근할 수 없다.

## 2. 계정과 팀 소속

```
계정 (User)  1 ── N  팀 소속 (Membership)  N ── 1  팀 (Team)
                      - 역할: TEAM_ADMIN | MEMBER
                      - 상태: ACTIVE | INACTIVE
```

- 계정은 로그인 단위다(아이디/비밀번호, 슬랙 연동은 계정에 1개).
- **역할과 활성 상태는 팀 소속마다 따로** 가진다. 1팀에서는 팀 관리자, 2팀에서는 팀원일 수 있다.
- 팀 이동이라는 기능은 없다. 다른 팀에서 일하게 되면 슈퍼 관리자가 **새 팀 소속을 추가**하고, 필요하면 **기존 팀 소속을 비활성화**한다.
- 소속이 비활성화되어도 그 팀에 남긴 데이터와 작성자 이름은 그대로 남는다.

### 로그인 흐름

1. 아이디/비밀번호 확인 (계정이 비활성이면 실패)
2. 활성 소속이 0개면 "소속된 팀이 없습니다"로 로그인 실패
3. 활성 소속이 1개면 그 팀으로 바로 진입
4. 활성 소속이 2개 이상이면 팀 선택 화면 → 선택한 팀으로 진입
5. 로그인 중에도 상단에서 다른 활성 팀으로 전환할 수 있다

## 3. 역할

| 역할 | 코드 | 범위 | 인원 |
|---|---|---|---|
| 슈퍼 관리자 | `SUPER_ADMIN` | 시스템 전체 (팀 데이터 제외) | 1명 이상 |
| 팀 관리자 | `TEAM_ADMIN` | 소속 팀 | **팀당 최대 2명** |
| 팀원 | `MEMBER` | 소속 팀 | 제한 없음 |

## 4. 팀별 설정 (슈퍼 관리자가 관리)

| 설정 키 | 기본값 | 의미 |
|---|---|---|
| `adminCanViewPrivate` | `false` | 팀 관리자가 팀원의 **비공개** TODO/이슈를 볼 수 있는가 |

> 팀 관리자는 팀원의 **공개** 내용은 항상 볼 수 있다. 이 설정은 비공개 항목에만 영향을 준다.

## 6. 소속 비활성화 정책

슈퍼 관리자가 어떤 사람의 특정 팀 소속을 비활성화하면:

1. 그 사람은 **그 팀으로 로그인/전환할 수 없다.** 다른 활성 팀은 그대로 사용한다.
2. 그 팀에 남긴 TODO, 이슈, 배포일정, 연차는 **그대로 남고** 작성자 이름도 유지된다. 이름 옆에 "(비활성)"이 표시된다.
3. 그 팀에서의 **반복 TODO 규칙은 중지**된다.
4. 그 팀에서의 **예약된 알림은 발송하지 않는다.**
5. 그 사람이 담당자인 **예정된 배포일정**은 그대로 두고, 담당자 이름에 "(비활성)"을 표시한다. 배포 등록자에게 "담당자가 비활성화되었습니다" 알림을 보낸다.
6. 다시 활성화하면 데이터 접근이 복구된다. 반복 TODO 규칙은 자동으로 재개하지 않는다(사용자가 직접 재개).

**계정 비활성화**는 모든 팀 소속을 비활성화한 것과 같게 처리하고, 로그인 자체가 막힌다.

## 7. 구현 메모

- 팀 필터는 서비스마다 손으로 넣지 않고 한 곳에서 강제한다(Hibernate `@Filter` + 요청마다 현재 팀 ID 주입). 빠뜨리면 바로 데이터 유출이 되기 때문이다.
- 현재 팀은 세션(또는 토큰)에 저장하고, 매 요청마다 **그 소속이 아직 활성인지** 확인한다. 비활성화 즉시 접근이 막혀야 한다.
- 권한 검사는 컨트롤러가 아닌 서비스 계층에서 한다.
- 팀 관리자 최대 2명 제한은 소속 추가/역할 변경 시 검증한다.
- 팀 격리는 모든 기능에 대해 테스트한다([features/tenant-isolation.feature](../features/tenant-isolation.feature)).
