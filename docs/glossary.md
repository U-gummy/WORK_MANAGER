# 용어집과 표준 문장 (v0.1)

> 이 문서는 사람(기획), AI(구현), 테스트(Step Definition)가 **같은 말을 같은 뜻으로** 쓰기 위한 기준입니다.
> .feature 파일의 모든 단계는 [6. 표준 문장 카탈로그](#6-표준-문장-카탈로그)에 있는 문장만 사용합니다.
> 새 문장이 필요하면 **먼저 이 문서에 추가**하고 나서 .feature에 씁니다.

## 1. 도메인 용어

| 용어 | 코드명 | 정의 | 쓰지 않는 말 |
|---|---|---|---|
| 사용자 | `User` | 로그인할 수 있는 계정을 가진 사람. 관리자 또는 팀원 | 회원, 유저 |
| 관리자 | `Role.ADMIN` | 계정과 설정을 관리하는 사용자. 항상 정확히 1명 | 팀장, 운영자, 어드민 |
| 팀원 | `Role.MEMBER` | 관리자가 아닌 사용자 | 멤버, 직원 |
| 계정 상태 | `UserStatus` | 활성 / 비활성 | 탈퇴, 삭제 |
| 위임 | `delegateAdmin` | 관리자가 다른 팀원에게 관리자 역할을 넘기는 것 | 양도, 이관 |
| 프로젝트 | `Project` | 몇 달 단위의 큰 일의 묶음. 관리자가 만들고 색을 정함. 뱃지로 표시 | 과제, 사업 |

| 플로우 링크 | `flowUrl` | 전사 협업 도구 "플로우"의 업무 주소. 업무와 TODO에 붙임 | 플로우 URL |

| 반복 TODO | `RecurringTodoRule` | 정해진 규칙에 따라 TODO를 자동으로 등록하는 규칙 | 정기 TODO, 루틴 |
| 반복 | `Recurrence` | 매일 / 평일 / 매주 {요일} / 매월 {n}일 | 주기 |

| 완료 | `TodoStatus.DONE` | TODO를 끝낸 상태 | 종료, 처리 |

## 2. 값 표기 규칙

| 종류 | 형식 | 예 |
|---|---|---|
| 날짜 | `YYYY-MM-DD` (요일은 쓰지 않음, 날짜로 계산) | `"2026-11-04"` |
| 시각 | `YYYY-MM-DD HH:mm` (한국 시간) | `"2026-11-04 13:50"` |
| 주 | `YYYY-MM-DD ~ YYYY-MM-DD` (월요일 ~ 일요일) | `"2026-11-02 ~ 2026-11-08"` |
| 월 | `YYYY-MM` | `"2026-11"` |
| 개수 | 숫자만 | `"3"` |

- 이름, 제목, 날짜, 상태, 화면 이름 등 **바뀌는 값은 모두 큰따옴표**로 감쌉니다. 숫자도 감쌉니다.
- 테스트 기준 인물: 관리자 `"박팀장"`, 팀원 `"김철수"`, `"최민수"`. 기준 날짜: `"2026-11-04"`(수요일).

## 4. 화면 이름

`{화면}에 {값}이 보인다` 같은 문장의 화면 자리에 쓰는 값입니다. 화면 이름이 곧 조회 대상이라, Step Definition은 이 표를 보고 어떤 API(또는 화면)를 확인할지 정합니다.

| 화면 이름 | 내용 |
|---|---|
| `대시보드` | 로그인 후 첫 화면 |
| `오늘 할 일`, `이번 주 할 일`, `오늘 부재자`, `다가오는 배포` | 대시보드의 영역 |
| `할 일 {날짜}` | 그날의 일 단위 TODO |
| `주간 할 일 {주}` | 그 주의 주 단위 TODO |
| `월간 할 일 {월}` | 그 달의 월 단위 TODO |
| `팀 TODO 목록` | 팀 전체 TODO |
| `TODO 등록 화면` | TODO 입력 화면 |
| `TODO 유형 선택 목록` | TODO 등록 시 고르는 유형 |
| `이슈 목록` | 전체 이슈 |
| `프로젝트 선택 목록` | TODO, 업무 등록 시 고르는 진행 중 프로젝트 |
| `업무 목록` | 전체 업무 |
| `업무 상세 {제목}` | 업무 하나의 TODO, 이슈, 배포 |
| `보고서 처리한 일`, `보고서 이슈`, `보고서 배포` | 월간 보고서의 영역 |
| `배포 캘린더 {날짜}`, `배포 캘린더` | 배포일정 |
| `배포 담당자 선택 목록` | 배포 담당자로 고를 수 있는 사용자 |
| `연차 캘린더 {날짜}`, `연차 캘린더` | 연차와 공휴일 |
| `관리자 위임 대상 목록` | 관리자를 넘길 수 있는 사용자 |
| `슬랙 설정 화면` | 팀 채널 설정 |
| `비밀번호 변경 화면` | 비밀번호 변경 |
| `메뉴 목록` | 점심 메뉴 |
| `팀원별 통계`, `월간 통계`, `완료한 TODO` | 통계 화면의 영역 |

## 5. 시나리오 작성 규칙

1. **선언형으로 씁니다.** "무엇이 일어나는가"를 쓰고 "어떻게 클릭하는가"는 쓰지 않습니다. 화면 조작은 Step Definition이 담당합니다.
2. **조건(Given)은 상태**로 씁니다. "~했다"(과거 행동)가 아니라 "~이 있다", "~이다"로 씁니다.
3. **시나리오 하나에 행동(When) 하나.** 결과(Then)는 여러 개여도 됩니다.
4. **권한이 없는 행동도 같은 문장**으로 씁니다. "~하려 하면"을 따로 만들지 않고, 결과에 `접근 거부 응답을 받는다`를 씁니다.
5. **조사는 자연스럽게** 씁니다. 받침에 따라 바뀌는 조사(이/가, 을/를, 은/는, 와/과, 으로/로, 이다/다)는 같은 문장으로 봅니다. Step Definition은 정규식 `(?:이|가)`처럼 작성합니다.
6. **시간은 테스트가 정합니다.** `오늘은`, `현재 시각은`, `시각이 ~이 되면`, `서버가 ~부터 ~까지 꺼져 있었다`로만 표현합니다. 코드는 `Clock`을 주입받아야 합니다.
7. **생략된 값은 기본값**입니다. TODO는 기간 "일", 날짜 "오늘", 상태 "미완료"이고, 상태가 "완료"인데 완료 시각이 없으면 그 TODO의 날짜에 완료한 것으로 봅니다. 사용자는 활성, 비밀번호 변경 완료 상태.
8. **"발송되지 않는다"**는 예약 시각이 지나도 발송되지 않음을 뜻합니다. Step Definition이 시간을 충분히 진행시킨 뒤 확인합니다.
9. **행동의 주어는 로그인한 상태**로 봅니다. `~이 로그인해 있다`는 세션 자체를 확인하는 시나리오에서만 씁니다.
10. **같은 제목의 TODO가 여럿이면** 행동이 가능한 것을 가리킵니다. 예를 들어 이월은 지연된 TODO에만 할 수 있으므로 지연된 쪽을 가리킵니다.
11. **데이터 표의 빈 칸**은 "없음"을 뜻합니다(예: 프로젝트 칸이 비어 있으면 프로젝트 없음).
12. **데이터 표의 열 이름**은 3장의 속성 이름과 같게 씁니다. 사용자 표: 이름, 아이디, 역할, 상태. TODO 표: 제목, 기간, 날짜, 유형, 프로젝트, 업무, 상태, 알림, 원래 날짜, 이월 횟수. 배포 표: 제목, 일시, 환경, 등록자, 담당자, 프로젝트, 업무, 상태. 이슈 표: 제목, 작성자, 프로젝트, 업무, 연결된 TODO, 원인, 해결, 상태. 프로젝트 표: 이름, 고객사, 색, 상태. 업무 표: 제목, 프로젝트, 작성자, 시작일, 종료일, 플로우 링크, 상태. TODO 표에는 플로우 링크 열도 쓸 수 있습니다.

## 6. 표준 문장 카탈로그

- `{...}` 자리에는 큰따옴표로 감싼 값이 들어갑니다.
- `{종류}`는 따옴표 없이 `TODO`, `반복 TODO`, `이슈`, `배포`, `알림`, `프로젝트`, `업무`, `고객사` 중 하나입니다.
- `{속성}`은 따옴표 없이 [7. 속성 이름](#7-속성-이름)의 이름을 씁니다. 예: `TODO "리팩터링"의 기간을 "주"로 바꾸면`
- 끝에 `:표`가 붙은 문장은 데이터 표가 이어집니다.
- 이 블록은 검사 스크립트가 읽습니다. 형식을 바꾸지 마세요.

### 6.1 조건 (Given)

```steps
다음 사용자가 있다 :표
{이름}이/가 로그인해 있다
{이름}의 계정 상태는 {상태}이다
계정이 하나도 없다
오늘은 {날짜}이다
현재 시각은 {시각}이다
서버가 {시각}부터 {시각}까지 꺼져 있었다
환경변수 {이름}이/가 설정되어 있다
환경변수 {이름}의 값은 {값}이다
환경변수 {이름}이/가 설정되어 있지 않다
슬랙 채널이 등록되어 있다
슬랙 채널이 등록되어 있지 않다
등록된 슬랙 채널이 슬랙에서 삭제되었다
{이름}의 슬랙 멤버 ID는 {값}이다
{이름}의 슬랙 멤버 ID는 없다
TODO 유형이 다음과 같다 :표
다음 프로젝트가 있다 :표
다음 업무가 있다 :표
{이름}에게 TODO {제목}이/가 있다
{이름}의 TODO가 다음과 같다 :표
{이름}에게 반복 {반복} TODO {제목}이/가 있다
{종류} {제목}에 이슈 {제목}이/가 있다
{이름}에게 이슈 {제목}이/가 있다
다음 배포가 있다 :표
다음 이슈가 있다 :표
{이름}에게 {날짜} {연차종류}이/가 있다
{날짜}은/는 공휴일 {이름}이다
{이름}에게 {시각}에 예약된 {알림종류} {제목}이/가 있다
{이름}에게 {날짜}에 만들어진 알림 {제목}이/가 있다
{이름}의 {기간} 완료율은 {값}이다
메뉴 목록이 다음과 같다 :표
메뉴 목록이 비어 있다
{날짜}의 룰렛 결과는 {메뉴}이다
{종류} {제목}의 {속성}은/는 {값}이다
```

### 6.2 행동 (When)

```steps
{이름}이/가 아이디 {아이디}, 이름 {이름}으로/로 계정을 만들면
{이름}이/가 {대상}의 비밀번호를 초기화하면
{이름}이/가 {대상}의 잠금을 해제하면
{이름}이/가 {대상}의 계정을 비활성화하면
```
